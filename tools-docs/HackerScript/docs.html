bootstrap self-hostujący się osiągnięty w 0.1

Zwykła fun kompiluje się
do prawdziwego Rusta.

HackerScript to język ogólnego przeznaczenia: statyczne typy i bezpieczeństwo pamięci Rusta na co dzień, z direct [ ... ] jako ucieczką do czystego Pythona dla małych fragmentów, które nigdy nie będą wymagały wydajności.

Zacznij → Pierwszy projekt 
struct Point [
    x: Int,
    y: Int
]

fun distance_squared(p: Point) -> Int [
    end (p.x * p.x) + (p.y * p.y)
]

fun main() [
    let p = Point(3, 4)
    log("dist^2 =", distance_squared(p))

    direct [
        print("To jest czysty Python wewnątrz binarki Rust.")
    ]
    end
]
Start

Wprowadzenie

fun → hackerc generuje prawdziwy Rust: struct staje się struct + impl new(), manual [...] staje się unsafe { ... }, List<T> staje się Vec<T>. Parametry typu struct/List/Str automatycznie dostają &/&mut zamiast przenoszenia własności.

direct [ ... ] → surowy Python wykonywany w trakcie działania programu przez Python::with_gil (PyO3, tryb auto-initialize) — Rust jest hostem.

Statyczne typy

Cały front — lexer/parser/typecheck/typeinfer — jest sam napisany w HackerScript.

Zero-cost

Kompilacja do Rusta oznacza brak własnego runtime'u ponad to, co daje rustc.

Self-hosted

hackerc i virus są dziś w całości napisane w samym HackerScript (.hcs).

Start

Instalacja

hackerc i virus to binarki natywne (self-hosted) — najprościej pobrać gotowe wydanie.

bash
curl -L --fail -o hackerc \
  https://github.com/HackerOS-Linux-System/HackerScript/releases/download/v0.1/hackerc
chmod +x hackerc

./hackerc check docs/hello-world/Virus.hk
./hackerc build docs/hello-world/cmd/main.hcs -o /tmp/out
cd /tmp/out && cargo run   # wymaga zainstalowanego Rusta
Uwaga: using <wersja> na początku pliku (lub [package] using w Virus.hk) deklaruje wymaganą wersję hackerc — jeśli nie jest zainstalowana, virus pobiera ją automatycznie z GitHub Releases.

Funkcje

end <wyrażenie> zwraca wartość i kończy funkcję. Ostatnie wyrażenie w bloku nie jest niejawnie zwracane — end jest zawsze wymagane, żeby coś zwrócić.

hcs
fun fib(n: Int) -> Int [
    if n <= 1 [
        end n
    ]
    end fib(n - 1) + fib(n - 2)
]
Składnia

Struktury i impl

hcs
struct Point [
    x: Int,
    y: Int
]

impl Point [
    fun sum(self) -> Int [
        end self.x + self.y
    ]
]

let p = Point(1, 2)
log(p.sum())

Generyczne deklaracje struct Box<T> / fun map<T,U> jeszcze nie istnieją planowane — List<T>/Dict<K,V> działają jako użycie generyków, nie deklaracja własnych.

Enum i match

hcs
enum Shape [
    Circle(Float),
    Rectangle(Float, Float),
    Empty
]

fun area(s: Shape) -> Float [
    match s [
        Circle(r) -> [ end 3.14159 * r * r ]
        Rectangle(w, h) -> [ end w * h ]
        _ -> [ end 0.0 ]
    ]
]

direct i manual

direct [ ... ] uruchamia surowy Python w trakcie działania programu (PyO3). manual [ ... ] transpiluje się do unsafe { ... } w wygenerowanym Ruście — do użycia świadomie.

Składnia

native {JavaScript}

Statycznie linkowany silnik JS — QuickJS przez rquickjs (kompilowany przez cc, nie zewnętrzny interpreter). console.log(...) jest polyfillem dopisywanym przez kompilator.

hcs
native {JavaScript} [
    const dane = { jezyk: "JavaScript", dziala: true };
    console.log(JSON.stringify(dane));
]

// import zewnetrznego pliku (sciezka wzgledna do .hcs)
native {JavaScript} <lib/utils.js> [
    console.log(funkcjaZUtilsJs());
]

Dziś tylko silnik "JavaScript" — inna nazwa daje komentarz, bez błędu kompilacji.

Składnia

$ polecenie $ — Zero-Cost Sandbox

Uruchamia polecenie powłoki w izolacji sieci i systemu plików przez libc::unshare(CLONE_NEWNET|CLONE_NEWNS) + bind-remount / na read-only — zero zewnętrznych narzędzi (firejail/bwrap). Brak uprawnień → ostrzeżenie na stderr, polecenie i tak działa, ale bez izolacji (nigdy cichy fejl).

hcs
$
whoami
echo "brak dostepu do sieci hosta i zapisu do /"
$
Ograniczenia: izoluje tylko ten podproces (nie resztę programu); polecenie nie może zawierać dosłownego $ (np. $HOME) — zamyka blok na pierwszym napotkanym.
Składnia

@hot_reload — podmiana kodu żywego procesu

Funkcja oznaczona @hot_reload trafia do osobnego, dynamicznie ładowanego cdylib. Wątek-obserwator śledzi plik .hcs i przy zmianie sam woła hackerc build + cargo build --release, po czym atomowo podmienia wskaźnik funkcji w działającym procesie — bez restartu.

hcs
@hot_reload
fun greet() [
    log("wersja 1")
    end
]
v1: tylko funkcje bez parametrów i bez wartości zwracanej, na najwyższym poziomie. Wymaga zmiennej środowiskowej HKS_HOT_OUT_DIR przy uruchomieniu (jawny błąd, jeśli brak) i ręcznego pierwszego builda hotlib/.

[package]
name = "hello-world"
version = "0.0.1"
using = "0.1"
edition = "2026"
authors = ["Twoje Imię"]

[dependencies]
# "pypi:rich" = "*"

[build]
entry = "cmd/main.hcs"
Narzędzia

CLI: hackerc i virus

KomendaCo robi
hackerc check plik.hcsparsuje + typechecking, bez generowania Rusta
hackerc build plik.hcs -o dirgeneruje crate Cargo w dir
virus init --name xtworzy nowy projekt z Virus.hk
virus build --releasepobiera właściwy hackerc wg using, buduje
virus install <pakiet>pobiera zależność z PyPI/crates.io/npm/JSR/Vira
virus fmt [--check]formatuje (lub sprawdza formatowanie) plików .hcs
virus linturuchamia diagnostyki hackerc na projekcie

Kolorowe wyjście (zielony = sukces, czerwony = błąd, cyan = nazwy) wyłącza się automatycznie, gdy ustawiona jest zmienna środowiskowa NO_COLOR.
